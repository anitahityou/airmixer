# AirMixer — Abstract Club

88 BPM 摄像头手势音乐台。所有声音本地合成，摄像头画面只在本机处理；不采集麦克风、不上传视频。

## 运行

需要 Node.js 22 或更新版本。在本目录打开终端：

```sh
npm install
npm run dev
```

打开 http://127.0.0.1:5173/，保持终端运行。也可双击「启动 AirMixer.command」。点击「开启摄像头并演奏」，允许摄像头权限。暂停/继续用画面内的播放按钮。

```sh
npm test
npm run build
npm run preview
```

预览地址 http://127.0.0.1:4173/。摄像头需要 localhost 或 HTTPS；不能直接双击 HTML。模型和 WASM 均随项目提供。

## 手势

- **朝镜头点击**：伸出食指，向镜头快速点一下再收回。使用指尖相对掌指关节的深度变化，整体移手不会被当作点击。
- **触屏点击**：开始播放后，用手指或触控笔直接点击画面；鼠标模拟模式仍不启用。
- **碰指点击**：食指与拇指先分开，再轻碰一下。接触稳定约 30 ms 发出一次低频重击 + 电子打击；分开稳定约 60 ms 后可再次点击。持续捏住不会连续重击，会进入 FX。
- **食指弯曲点击**：其余三指收起，食指伸直、弯下、再伸直，也可触发重击。
- **左右移动**：控制滤波亮度；**上下移动**：下一拍改变音乐层次。
- **快速上/下滑**：立即触发 Acid 扫音，不等待节拍队列；**横挥**：下一小节转场。
- **张手 / 合手**：稳定切换姿势后，合手立即重击、张手立即和弦爆发。握拳仍进入 Breakdown。首次入镜和丢手重连不自动发声。
- **V 手势**：碎拍；**摇滚手势**：Rave 和弦；**张掌侧倾**：回旋。
- **双手张开拉远**：空间泛音；拉远后合拢触发和弦收束。两只手入镜时也支持拇指与食指点击。

主界面仅保留摄像头演奏和播放器。Demo、鼠标/键盘模拟演奏及参数面板已移除。离开页面释放摄像头，回来点击摄像头重新连接。

## 声音与反馈

整套伴奏改为 Club Groove：124 BPM 四拍底鼓、白噪声军鼓/踩镲、锯齿酸性贝斯、失谐短和弦、方波序列及噪声尾音。A minor / C major 兼容和声，8 小节循环。

点击使用独立音源立即发声，不进入节拍队列。低频重击叠加 FM 打击，背景伴奏短暂降至约原电平的三分之一，并在 240 ms 内恢复；总压缩和限幅保留。视觉每次轮换六种霓虹颜色，已识别点击会显示「重击 · 次数」。

## 排查

- 页面拒绝连接：重新运行 `npm run dev`。
- 无画面：允许浏览器摄像头权限，关闭占用摄像头的应用，再点击摄像头。
- 有画面无骨架：确保手完整入镜、照明足够、手指未遮挡。
- 有骨架但无「重击」计数：先把拇指与食指明显分开，再碰合；手指不能一直贴在一起。
- 有「重击」计数但无声音：检查播放器、浏览器标签静音和系统输出设备。

测试使用模拟关键点及音频接口，实际设备听感、识别率和端到端延迟仍需实测。可选浏览器检查见 tests/browser-check.mjs。

## 动作共同编曲
每个动作先保留即时反馈，再留下跟拍乐句：点按 / V 手势加入八小节节奏，合手加入十六小节低音，张手 / 扫奏 / 双手合奏铺开十六小节和弦，上下滑动 / 回旋加入八小节旋律，回声和转场留下八小节尾奏。124 BPM 下分别约 15 秒和 30 秒，另有自然尾音。

声部分别叠加，所有音符取自当前伴奏和弦；重复同类动作续写对应声部，不无限增加循环。停止互动后声部逐渐结束，暂停会清空乐句，继续播放不会重放旧动作。

长乐句会每两小节改变旋律或节奏音型，并在最后两小节淡出。重复动作延长对应声部的存续时间，保留已经进行到的乐句位置，使新动作接入正在演奏的音乐。

## DJ 回声与双手弦线
所有动作乐句保持至少八小节（约 15 秒）；和弦 / 低音十六小节（约 30 秒）。这是持续发展的声部，而非将单个音硬拉长。


界面恢复为单个流动的抽象线环，随音乐频谱起伏；摄像头上叠加手骨架与可演奏弦线。界面没有恢复 Demo 和参数卡片。音乐降低到 124 BPM，采用三和弦加八度、固定短旋律、较柔和的音色；手势声部加入时伴奏同类声部让位。

双手张掌稳定入镜后，中间连接线可演奏：

| 动作 | 乐句 | 时长 |
| --- | --- | --- |
| 拉开 | 展开的和弦 | 约 30 秒 |
| 收拢 | 收束和弦 | 约 30 秒 |
| 双手上移 | 上行旋律 | 约 15 秒 |
| 双手下移 | 下行旋律 | 约 15 秒 |
| 一高一低、倾斜 | 摇曳旋律 | 约 15 秒 |

触发时弦线变色、加粗并振动。保持不动不重复触发，动作之间至少间隔 1 秒；丢手重入时先建立位置基准。相同声部只续写，不无限叠加。暂停清空乐句。

## Club Groove：统一节拍与混音
- 统一 124 BPM 时钟：底鼓固定四拍，反拍踩镲，2 / 4 拍军鼓，细小十六分摆动；所有延迟时值随相同 BPM。
- 鼓组走干声通道，贝斯独立单声道，不经过手势混响。旋律与低音在每次底鼓落下时短暂降低，下一拍前恢复。
- 点击保留即时轻短反馈，节奏 / 低音 / 旋律下一拍加入，和弦下一小节加入；不再额外打入离拍的超低频重击。
- 手势节奏使用专用打击音色，低音复用单一贝斯声部，不与原有贝斯叠加；旋律与伴奏共享同一和声。
- 转场在完整 8 小节边界执行，最后一小节加入鼓填充并短暂让出低音，进入下一段时恢复。界面显示剩余小节数。

口播和浏览器语音调用已移除。替代效果使用音频时钟同步的八分音符回声，每小节加入一次当前和弦内的音符，每四小节带一次柔和滤波展开；效果声部随动作维持约 15 秒，可续接。反馈上限 32%，通过旋律侧链与总限幅，避免低频回声堆积。

视觉新增碎裂掉落：每次音效触发从对应位置迸出彩色玻璃状碎片，带裂纹、旋转、重力下落与淡出。重击和和弦产生 24 片，其他事件 16 片；最多 240 片同时存在，减少动态效果设置下只显示静态淡出。

## 当前版本：和弦演奏
交互音效统一改为和弦音色：

| 动作 | 和弦 |
| --- | --- |
| 点击 | Cadd2 |
| 张手 / 扫奏 | Cmaj7 |
| 合手 / 左旋 | Em7 |
| 上滑 / 右旋 / 双手拉开 | Fmaj7 |
| 下滑 / 双手收拢 | Fm6 |
| V 手势 / 双手倾斜 | C9 |

每次动作立即播放和弦，后续 15–30 秒乐句继续按节拍演奏。最新动作决定当前和声，全体旋律声部和贝斯根音跟随切换，旧和弦尾音平滑释放，避免 Fm6 的 Ab 与旧 Fmaj7 的 A 长时间叠加。C9 包含 Bb（属七音），区别于 Cmaj9。屏幕同步显示当前和弦名。鼓组和 124 BPM 的律动保留。

## 钢琴式长延音
手势和弦使用明亮起音、自然衰减的 FM 钢琴式合成音色（非钢琴采样）。每个音至少保持 10.5 秒，再用 1.6 秒尾音释放；和弦由 -21 dB 提高至 -15 dB，同时提高触键力度。新动作不会切断此前弹出的钢琴音，重复同音重新起音并续长；每个音高只使用一个音源，避免快速连点无限叠音。暂停会释放所有长音。

## 当前演奏与曲风

播放器内选择 Piano House（默认）或 UK Garage；两者统一 124 BPM，下一小节切换鼓点、低音律动与摇摆，切换不会重启演奏。轻触采用更短的确认时间，前推和滑动需要的幅度降低；保留松开后重新触发、抖动过滤与丢失跟踪复位。

互动钢琴起音加大、持续音量提高，伴奏鼓与低音降低以突出触键。每次和弦仍保持 10.5 秒再释放；换和弦时旧和弦独有的音降低到背景，共同音保留，避免长延音不断堆积。和弦声部、单音旋律与根音低音分工，后续乐句随当前和弦变化。

刷新页面（Mac：⌘⇧R）后生效。声音为本地合成，实际响度和识别灵敏度需要结合摄像头与扬声器试听。

## 当前和弦模式：《bad guy》主循环

有效交互按 Gm → Cm → D7 → Gm 顺序推进，动作类型改变声部，但不再各自绑定旧的 Cadd2 / Fmaj7 等和弦。首次触发为 Gm。低音、旋律与回声跟随当前和弦；自动伴奏不消耗和弦步骤。暂停不推进，继续时保留位置。转场在实际落拍时推进。

这是基于歌曲主和声的交互循环，不是原曲的完整段落、时值或录音复刻；保留现有 124 BPM 与 House / Garage 伴奏及 10.5 秒延音。

## 当前底层伴奏：Chill Drift

底层已替换为 88 BPM 迷幻 Chill 合成伴奏：稀疏底鼓与半拍军鼓、柔和低音、慢起音铺底、稀疏拨弦、长混响与附点八分延迟。播放器仅显示曲名，不再提供 Piano House / UK Garage 选择。此节替代此前曲风切换与 124 BPM 的说明。手势的 Gm → Cm → D7 循环与至少 10.5 秒延音仍保留。

## 新增姿势与线条波纹

- 手背：先掌心朝向摄像头张开约半秒完成校准，再翻手展示手背。只判断稳定且较正面的手；追踪丢失后重新校准。它是基于掌面方向翻转的启发式识别，不是手背图像分类。
- 单根手指：其余手指收起，伸出一根手指，保持约 220ms。
- 竖大拇指：四指收起，拇指向上伸直；不进入握拳 Breakdown。
- 比耶：食指、中指分开伸直，其他手指收起。
- 快速挥动：张掌快速横向移动，立即触发和弦，保留 3 秒冷却。

静态姿势每次只触发一次，回到正面张掌后重新触发。以上动作在单手、双手模式均接入和弦循环，反馈为彩色细线波纹；其他原有动作保留碎片效果。减少动态效果设置下波纹静止淡出。手背校准依赖起始掌心姿势，真实镜头环境需实测。

## 指尖视觉联动

触发事件携带触发手的坐标快照，双手演奏的波纹分别从各自指尖/掌心发出。指尖增加 220ms 短轨迹和定位环；指尖点按使用细线波纹，手边显示和弦和动作。中央抽象线条随食指位置偏移。失去跟踪后清理轨迹；减少动态效果时关闭轨迹与跟手偏移。

技术选择：继续用 TypeScript + Canvas + MediaPipe Worker + Tone.js/Web Audio。TypeScript 提供类型检查，编译后仍是 JavaScript；性能优化应依据实测，优先处理坐标同步、绘制负载与识别耗时。只有绘制成为瓶颈时再考虑 WebGL，自定义音频处理需要时再引入 AudioWorklet。

## 玻璃水面视觉

摄像头原色完整显示人像，保持 contain 投影以对齐触点。摄像头开启时移除中央线环、淡化手骨架。交互在实际触点产生约 3.2 秒透明涟漪，波纹边缘用实时画面的局部缩放模拟折射，辅以亮边与暗边。替代旧碎片/彩色爆发效果；背景伴奏不自动激起水纹。最多同时 6 组、每组 4 层，减少动态效果时仅静态淡出并停用折射。

## 录屏参考：液态玻璃折射

根据用户提供的 6 秒录屏关键帧，采用 WebGL 对实时摄像头纹理作局部位移，模拟玻璃水滴鼓起、弯曲波前和多触点叠加。每次触发持续约 4.5 秒，最多 6 个波源，渲染像素比上限 1.25。未受波源影响的区域透明，露出原始摄像头画面。WebGL 创建/编译失败、纹理上传失败或上下文丢失时退回 Canvas 涟漪；减少动态效果设置下禁用动态折射。模型与音频逻辑保持不变。
